# 默认审核交付模板

## 一、审核结论

- 结论：可发布 / 修改后可发布 / 建议重写 / 暂缓并确认
- 总分：__/100
- 问题统计：P0 __ 项，P1 __ 项，P2 __ 项，P3 __ 项
- 一句话判断：说明最关键的发布条件。

## 二、审核依据与待确认信息

- 已使用材料：列出文件或用户信息。
- 关键要求：概括本次 brief 基线。
- 缺失/冲突：列出对结论有影响的缺口。
- 审核假设：明确所有推断。

## 三、优先问题清单

| 等级 | 位置 | 原文/现状 | 问题与影响 | 建议修改 | 确认方 |
|---|---|---|---|---|---|
| P0–P3 | 段落/页码/镜号/时间码/单元格 | 精简引用 | 具体原因 | 可替换文案或动作 | 达人/品牌/法务 |

## 四、评分

| 维度 | 得分 | 扣分依据 |
|---|---:|---|
| 事实与合规 | /25 | |
| Brief 完成度 | /25 | |
| 达人风格融合 | /20 | |
| 内容与转化逻辑 | /15 | |
| 平台适配与可执行性 | /15 | |

## 五、Brief 完成度

使用 review-rubric.md 的 Brief 对照表，逐项给出稿件证据。

## 六、达人风格与大纲匹配

- 达人账号与样本范围：主页链接、采集日期、篇数、覆盖时间。
- 稳定风格：标题、开篇、叙事、语言、产品露出、收尾。
- 近期爆文形式：代表笔记、互动数据、结构拆解与样本边界。
- 当前大纲匹配：符合 / 部分符合 / 不符合 / 样本不足，并提供证据。

## 七、逐条修改建议

按稿件顺序提供“原文 → 建议改为 → 理由”。没有问题的段落无需重复。

## 八、完整优化稿

保留原稿的内容形态和达人语言特征。所有未确认信息使用 `[待确认]`，不得把占位符当成发布文案。

## 九、发布前人工核对

- 产品名、规格、价格、活动日期与链接。
- 必带词、话题、账号、商业合作标识。
- 功效、数据、排名、检测和背书证据。
- 达人真实体验、素材版权、人物授权。
- 口播时长、字幕、画面、封面与最终剪辑。
- 品牌、达人、法务需要确认的所有占位项。
