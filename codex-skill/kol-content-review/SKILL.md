# 达人投放稿件审核

## 核心原则

- 同时维护品牌准确性与达人原生感。不要把稿件改成品牌新闻稿。
- 区分“brief 明确要求”“基于材料的推断”“审核建议”。不得补造产品卖点、体验、数据、功效或达人经历。
- 优先指出会阻止发布的问题，再处理表达优化。
- 每个问题都给出位置、原因和可执行改法；能直接改写时提供替换文本。
- 保留达人稳定的口头禅、句式、节奏和内容结构，除非它们造成事实、合规或品牌风险。
- 只做审核建议与修改初稿，最终定稿、法务判断和发布决定必须由人工完成。

## 选择输入处理方式

1. 读取用户提供的 brief、产品资料、达人资料、稿件及补充要求。
2. 对 `.docx`、`.xlsx`、`.pdf` 等文件，调用对应文档技能提取内容并尽量保留页码、段落、单元格或时间码定位。
3. 多文件时先建立对应关系：品牌/产品资料、达人参考、待审稿件、历史反馈。不要把不同达人或不同产品的信息串稿。
4. 若材料包含链接且审核依赖其内容，读取链接；若用户要求核对当前平台规则、法规或产品公开信息，联网核验并注明来源与日期。

## 建立审核基线

先从材料中整理一份“本次审核依据”，至少包括：

- 平台与内容形态：小红书图文/视频，或抖音短视频/口播等。
- 传播目标、目标人群和核心信息。
- 必须出现的产品名、卖点、使用场景、活动信息、话题、账号或行动引导。
- 禁止出现或需要谨慎处理的说法。
- 从稿件识别到的达人姓名与小红书主页链接。
- 交付限制：字数、时长、画面、发布时间、修改轮次等。

不完整时不要停住整个审核。列出“缺失信息与假设”，先完成能够确定的部分；只有缺失项会实质改变结论时，才请求补充。

详细提取方法见 [references/intake.md](references/intake.md)。

## 自动建立达人风格基线

不要要求用户单独提交达人风格资料。先从稿件抬头、文件名、正文或备注中提取达人姓名与小红书主页链接；链接优先于同名搜索结果。无法唯一识别时，要求用户补充主页链接，不要猜测账号。

识别成功后，先估算并说明外部采集调用量；采集可能产生费用时，必须等待用户明确确认。确认后读取该主页近期公开内容，优先覆盖近 30–90 天，并至少提取：

- 稳定内容形式：常用选题、标题钩子、开篇方式、叙事顺序、产品出现时点、互动收尾。
- 语言与人设：视角、长短句、语气词、专业度、情绪强度、固定表达。
- 近期爆文形式：按互动表现识别代表内容，记录标题、内容结构、发布时间与互动数据；不得只凭单篇判断长期风格。
- 样本边界：采集篇数、时间范围、数据完整性、可能的商业稿比例与异常值。

将稿件大纲与风格基线逐项对照，输出“符合 / 部分符合 / 不符合 / 样本不足”，并引用达人历史内容证据。不要机械复制爆文标题或达人原句，也不要把爆文结构等同于必然效果。

## 执行四层审核

按顺序审核，避免只做润色：

1. **红线层**：事实错误、无依据宣称、绝对化/功效化表达、潜在违法违规、价格活动错误、竞品或舆情风险。
2. **交付层**：必带信息是否齐全、核心卖点是否准确、产品露出是否自然清晰、话题/账号/行动引导是否符合 brief。
3. **内容层**：开头是否有吸引力，场景—痛点—体验—卖点—结论是否连贯，信息是否重复，口播与画面是否匹配。
4. **达人风格层**：大纲、钩子、叙事顺序、表达节奏与互动方式是否符合达人近期内容及爆文形式。
5. **原生层**：是否符合平台消费习惯，是否广告腔过重，产品植入与互动设计是否自然。

使用 [references/review-rubric.md](references/review-rubric.md) 的评分与问题分级；根据平台读取 [references/platform-guides.md](references/platform-guides.md)。涉及风险表述时读取 [references/risk-guide.md](references/risk-guide.md)，但不要把其中示例当作穷尽清单或正式法律意见。

## 修改稿件

- 先做最小必要修改，尽可能保留达人原句和个人节奏。
- 对高风险或关键卖点问题，给出“原文 → 建议改为 → 修改理由”。
- 对结构性问题，重排段落或镜头，并说明为什么调整顺序。
- 资料不足的内容使用 `[待品牌确认：…]`，不得自行填数或替品牌承诺。
- 视频稿尽量保留或补全“时间/镜号、画面、口播/字幕、产品露出、备注”；图文稿分别审核标题、封面、正文、图片顺序、话题与评论区引导。
- 若用户只要求审核，不要静默重写全文；先交问题清单，再提供可选优化稿。

## 输出交付物

默认使用 [references/output-template.md](references/output-template.md) 的中文格式，依次输出：

1. 审核结论：可发布 / 修改后可发布 / 建议重写 / 暂缓并确认。
2. 本次审核依据、缺失信息与假设。
3. 高优先级问题清单，并精确定位原文。
4. 完整度与质量评分，以及扣分依据。
5. 达人风格基线、近期爆文结构与大纲匹配判断。
6. 逐条修改建议。
7. 保留达人风格的完整优化稿。
8. 发布前人工核对清单。

批量审稿时，每位达人独立成节或独立表格行，另给项目级共性问题汇总。不要用平均分掩盖单篇红线。

## 完成前自检

- 每个必带项都有“已满足 / 未满足 / 待确认”的证据。
- 所有产品数据、功效、价格、活动和体验描述都能追溯到材料。
- 没有为了顺口而改变事实含义。
- 修改稿仍能听出达人本人，而不是统一的品牌口吻。
- 视频口播在目标时长内可执行，图文标题与正文相互兑现。
- 高风险项明确要求人工、品牌或法务确认。
- 最终稿与问题清单一致，没有把已识别风险重新写回。
